# Proposal

## Why

Существующие CLI отдельно получают Markdown, строят chunks, semantic и lexical snapshots, но не обеспечивают одну полную переиндексацию с остановкой приложения и восстановлением обслуживания. Следующий обязательный этап ROADMAP.md и SPEC.md §7, §27 — публиковать только полностью согласованный индекс и сохранять рабочее состояние при любой ошибке сборки.

## What Changes

- Добавить административную команду `./reindex.sh`: блокировка повторного запуска, остановка только `app`, one-shot индексатор через Compose и повторный запуск `app` после успеха или ошибки.
- Добавить `python -m app.indexer`, объединяющий полный read-only ingestion → chunking → SQLite → локальные E5 embeddings → FTS5. Все промежуточные файлы строятся отдельно от активного индекса.
- Проверять и закрывать готовый SQLite snapshot до единственной атомарной замены активного файла; документы, embeddings, FTS и metadata принадлежат одному поколению.
- Сохранять в том же файле время последней успешной индексации и counts; при restart загружать согласованные данные из опубликованного файла. Отсутствие/несовместимость индекса обозначать явно во внутреннем состоянии, сохраняя существующий startup/health без индекса.
- Добавить проверки успеха, удаления страниц, пустого корпуса, отказов на этапах сборки/публикации, взаимного исключения и restart; подготовить эксплуатационную инструкцию и фактическую серверную проверку.

## Capabilities

### New Capabilities

- `atomic-full-reindex`: сквозная административная пересборка, атомарная активация единого SQLite поколения, восстановление приложения и загрузка опубликованного состояния после restart.

### Modified Capabilities

Нет. Контракты отдельных ingestion/chunking/storage/retrieval CLI сохраняются; orchestration добавляется поверх них. Пустой startup и текущий `/health` остаются доступны. Устаревшие исторические формулировки о блокирующем Hit@5 в main hybrid spec не меняются этим change; действующие критерии задаёт SPEC.md.

## Impact

- Новые `reindex.sh`, `app/app/indexer.py`, небольшой модуль состояния активного индекса и целевые тесты; связанные изменения `app/app/config.py`, `app/app/main.py`, `compose.yaml`, `.env.example`.
- Переиспользуются `ingestion`, `chunking`, `index_storage`, `semantic_storage`, `lexical_storage` и их validators; новые зависимости и внешние сервисы не требуются.
- Эксплуатационная документация в `docs/atomic-full-reindex.md`; README.md и ROADMAP.md не изменяются.
- Во время reindex `app` недоступен; LLM и Wiki.js продолжают работать. Нужны место на data filesystem для staging и заранее установленные E5 assets, доступ к подготовленному read-only view.
- Вне scope: hot reload, incremental indexing, очереди, расписание, HTTP reindex endpoint, chat/UI/расширение health, tuning retrieval и достижение Hit@5 ≥90%.
