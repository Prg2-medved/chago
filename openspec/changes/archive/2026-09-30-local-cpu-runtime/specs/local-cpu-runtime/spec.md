# Spec Delta

## Purpose

Обеспечить локальный CPU-only запуск выбранной LLM, проверку её HTTP API и измерение ресурсов на целевом сервере до реализации поиска и RAG.

## ADDED Requirements

### Requirement: Local CPU model serving
Сервис llm SHALL запускать Qwen3-4B-Instruct-2507 GGUF Q4_K_M через llama.cpp server только на CPU, без GPU/CUDA. Начальная конфигурация SHALL использовать context 8192, CPU threads 8 и максимум одну активную генерацию. Порт LLM SHALL быть доступен app во внутренней сети Compose без публикации на хосте.

#### Scenario: Start prepared runtime
- **WHEN** оператор подготовил локальный GGUF и образы и запускает docker compose up
- **THEN** работают app и llm, LLM использует CPU и доступна app по внутреннему HTTP-адресу

#### Scenario: Concurrent generation requests
- **WHEN** в llm одновременно поступают два запроса генерации
- **THEN** одновременно обрабатывается не более одной генерации, второй запрос ожидает освобождения единственного слота

### Requirement: Host model and configuration-only replacement
GGUF SHALL храниться на хосте вне Git и подключаться read-only. Путь SHALL задаваться через LLM_MODEL_PATH. App SHALL получать базовый HTTP-адрес LLM через LLM_BASE_URL и имя модели через LLM_MODEL_NAME. Runtime SHALL поддерживать замену совместимого GGUF и имени через настройки с пересозданием llm без изменения Python-кода. Автоматическое скачивание или выбор удалённой модели SHALL отсутствовать.

#### Scenario: Replace local file
- **WHEN** оператор задаёт путь другого локального совместимого GGUF и при необходимости новое имя модели, затем пересоздаёт llm
- **THEN** health и тестовая генерация используют выбранную модель без редактирования Python-кода

#### Scenario: Missing or invalid model
- **WHEN** указанный файл отсутствует, недоступен или не поддерживается выбранным llama.cpp
- **THEN** llm не объявляет готовность, выдаёт диагностируемую ошибку и не скачивает замену

### Requirement: Explicit LLM readiness check
Административная команда из окружения app SHALL проверять GET /health llama.cpp по LLM_BASE_URL с конечным timeout и сообщать успех только при HTTP 200 и status=ok. Загрузка, недоступность, некорректный ответ и истечение timeout SHALL давать понятную ошибку и ненулевой exit code. Эта проверка SHALL быть отдельной от существующего GET /health приложения.

#### Scenario: Ready model
- **WHEN** модель загружена и оператор выполняет проверку LLM
- **THEN** команда подтверждает готовность и завершается с кодом 0

#### Scenario: Loading or unreachable model
- **WHEN** llama.cpp возвращает 503, недоступен или не отвечает до timeout
- **THEN** команда не сообщает готовность и завершается с ненулевым кодом, а app-only /health сохраняет свой контракт

### Requirement: Russian chat completion smoke check
Административная команда SHALL отправлять тестовый POST /v1/chat/completions в локальный llm с настроенным именем модели, коротким русским вопросом и без RAG-контекста. Начальные параметры SHALL быть max_tokens=768, temperature=0.2, top_p=0.8, top_k=20. Команда SHALL выводить непустой ответ и доступные timings; содержательность и русский язык SHALL проверяться человеком на целевой модели. HTTP-ошибка, пустой/некорректный ответ или timeout SHALL завершать проверку с ошибкой без автоматического повторного запроса генерации.

#### Scenario: Successful Russian answer
- **WHEN** выполняется smoke check на готовой Qwen
- **THEN** получен непустой choices[0].message.content и проверяющий подтверждает связный ответ на русском по заданному вопросу

#### Scenario: Failed completion
- **WHEN** LLM возвращает ошибку, пустой ответ или не отвечает до timeout
- **THEN** команда завершается с ненулевым кодом и не объявляет проверку успешной

### Requirement: Offline model runtime
После предварительной подготовки образов, зависимостей и GGUF запуск, перезапуск, LLM health и генерация SHALL работать без интернета при сохранённой внутренней связи app–llm. Веса SHALL не включаться в Git или образ приложения; startup SHALL не устанавливать пакеты и не скачивать модели.

#### Scenario: Offline restart and completion
- **WHEN** внешний доступ отключён после установки и сервисы запускаются, затем перезапускаются
- **THEN** app health, LLM health и тестовая генерация успешны без внешних запросов

### Requirement: Target server benchmark evidence
Документация SHALL содержать воспроизводимую процедуру и фактический результат на Intel Core i5-14400 с 15 ГиБ RAM без GPU: время до готовности после запуска llm, RAM хоста и контейнера до/после загрузки, generation tokens/sec на одном фиксированном коротком русском запросе. Результат SHALL указывать дату, параметры, образ/версию llama.cpp, идентичность GGUF, вопрос/ответ, метод измерения и влияние на память/отзывчивость существующих сервисов. Постоянный swap/thrashing SHALL считаться проблемой приёмки. Фиктивные числа, результаты другой машины и незаполненный шаблон SHALL не считаться выполнением критерия.

#### Scenario: Record actual benchmark
- **WHEN** проверяющий выполняет процедуру на целевом сервере
- **THEN** сохраняются реальные значения с единицами и источником timings, включая отдельное время генерации для расчёта tokens/sec

#### Scenario: Target unavailable
- **WHEN** целевой сервер недоступен или измерения не выполнены
- **THEN** benchmark остаётся явно непроверенным и соответствующая задача не отмечается завершённой
