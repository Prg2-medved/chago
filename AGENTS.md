# AGENTS.md

## Общие правила

Работай только в рамках поставленной задачи.

Перед изменением кода:
- читай только файлы, непосредственно связанные с задачей;
- переходи по зависимостям только при необходимости;
- не сканируй весь репозиторий без причины;
- не делай несвязанный рефакторинг.

Предпочитай минимальное изменение, достаточное для решения задачи.

Не изменять `README.md` без явного запроса пользователя.
Не изменять `ROADMAP.md` без явного запроса пользователя.

## Источники истины и OpenSpec

- `SPEC.md` задаёт требования и критерии приёмки; `ROADMAP.md` — последовательность этапов и briefs, без статусов выполнения.
- OpenSpec хранит конкретные proposal/design/specs/tasks и фактическое состояние реализации; исторические отчёты фиксируют результаты экспериментов, а не новые требования.
- Действующие критерии MVP и post-MVP определяются `SPEC.md`.
- Для нового этапа создавай отдельный OpenSpec change по brief из roadmap; согласуй planning artifacts перед реализацией. Не переиспользуй архивированные changes и не переписывай исторические результаты.
- Отмечай tasks выполненными только после фактических проверок. При архивировании принятых изменений стандартный путь — синхронизация delta specs; для отрицательных экспериментов по решению владельца допускается `archive --skip-specs`. Перед архивированием выполни `openspec validate --all --strict`.

Полный набор тестов запускай только если изменение потенциально влияет
на несколько компонентов или это явно требуется задачей.
